# UI voor de DoD van M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** één pagina in de SPA van #68 die de open vragen, de teruggegeven issues en het
usage-venster van Claude en Codex toont en zichzelf ververst, bewezen met Playwright tegen de
gebouwde binary in CI en met een screenshot tegen CorneeldH/personal_ai_agent.

**Architecture:** `lighthouse serve` krijgt `--forge-url`, zodat een test een nep-GitHub kan
aanwijzen. In `web/` komt TanStack Query tussen de orval-client en de componenten: één module met
de fetchers en de foutvertaling, één met de query-hooks, daarna presentatiecomponenten per blok.
Playwright start per scenario een nep-GitHub in Node en de echte binary met tijdelijke
`XDG_CACHE_HOME`, `HOME` en `--db`.

**Tech Stack:** Go 1.26.4 met Cobra; Node 22.22.2 met npm; React 19, TypeScript, Tailwind v4,
shadcn/ui, vitest met Testing Library (alles uit #68); `@tanstack/react-query` v5;
`@playwright/test` met alleen Chromium; GitHub Actions.

**Spec:** [2026-10-27-ui-m1-dod-design.md](../specs/2026-10-27-ui-m1-dod-design.md)

## Global Constraints

- **Start pas als #68 op `main` staat.** Rebase deze branch eerst op `main`; zie *Vóór Task 1*.
- Code, commentaar, namen en alle zichtbare UI-tekst in het Engels; plan en commitberichten in het
  Nederlands, als Conventional Commits met `(#69)`.
- Vaste UI-teksten, letterlijk:
  - `No open questions`
  - `No returned issues`
  - `Forge not configured — set GH_TOKEN and --repo` (status 503)
  - `Forge unreachable: <detail>` (elke andere niet-200; `<detail>` uit de problem+json, anders
    `HTTP <status>`)
  - `Server unreachable` (de fetch zelf faalt)
- Intervallen: usage `30_000` ms, forge-lijsten `300_000` ms. `retry: false` op de QueryClient:
  het interval is de herhaling, en een retry vertraagt de foutmelding.
- De UI stuurt op `state` (`ok | stale | not_measurable`), nooit op `pct`. Bij
  `not_measurable` rendert hij geen `%`.
- Geen `fetch(` buiten `web/src/api/`: alle data via de orval-functies `getQuestions`,
  `getReturned`, `getUsage`, `getHealth`.
- `web/src/api/` en `web/openapi.json` niet met de hand wijzigen. #69 verandert geen API-schema.
- Installeren met `npm ci`; nieuwe pakketten met een exacte versie (`--save-exact`).
- Geen derde `go test`-stap in `ci.yml` (`tests/test_ci_go_test_pin.py`); actions op een
  volledige SHA met de tag als commentaar.
- Playwright draait niet in de lokale test-gate, wel in CI.

## Review Focus

1. **`--forge-url` met een slash aan het eind** (`http://127.0.0.1:9999/`): de client plakt
   `/repos/...` erachter en vraagt `//repos/...`, wat een nep-server en GitHub Enterprise niet
   kennen. Verwacht: de slash valt weg. → test in Task 1.
2. **Een 502 zonder `detail`** (een proxy die HTML geeft): de foutvertaling mag niet crashen op
   het lezen van de body. Verwacht: `Forge unreachable: HTTP 502`. → test in Task 2.
3. **`pct: 0` met `state: ok`** (een vers venster): dat is een echte 0% en moet als `0%` met een
   lege balk staan, niet als "not measurable". De keerzijde van de anti-goal. → test in Task 3.
4. **Een vraagtekst met regeleinden en `<script>`**: platte tekst, regeleinden behouden, niets
   als HTML. → test in Task 4.
5. **GITHUB_TOKEN in de omgeving van CI**: het 503-scenario faalt als de fixture de omgeving
   van het testproces erft. Verwacht: de fixture bouwt de omgeving van serve zelf op. → scenario
   `503` in Task 6.
