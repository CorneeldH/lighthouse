# Pins voor overgenomen skills, Superpowers en tools — implementatieplan (#325)

> **Voor agentic workers:** VERPLICHTE SUB-SKILL: gebruik superpowers:subagent-driven-development (aanbevolen) of superpowers:executing-plans om dit plan taak voor taak uit te voeren. Stappen gebruiken checkbox-syntax (`- [ ]`).

**Doel:** Elke afhankelijkheid van lighthouse (overgenomen skills en bestanden, Superpowers, kenn-forge, roborev, codex) heeft een beoordeelde pin; `lighthouse pins check` meldt per pin `current`, `behind` of `error`, en een wekelijkse lane biedt een achterstand aan als draft-PR of issue.

**Architectuur:** Pakket `internal/pins` meet (upstream via bare partial clone en release-API, lokaal via `installed_plugins.json` en `<tool> version`); `lighthouse pins check` is de CLI erop. Een tweede laag in hetzelfde pakket (`lane`) vertaalt een uitkomst naar acties (twee sporen, markers) en voert ze uit via `internal/forge`, dat de schrijfmethodes erbij krijgt. Een dunne workflow `.github/workflows/pins.yml` draait `lighthouse pins lane`.

**Tech Stack:** Go (cobra, BurntSushi/toml, al in `go.mod`), `git` (bare clone, `merge-file`), GitHub REST via `internal/forge`; pytest voor `tests/test_sources.py`.

**Spec:** [`../specs/2026-11-15-issue-325-pins-design.md`](../specs/2026-11-15-issue-325-pins-design.md)

**Indeling:** drie delen, elk een eigen PR en los te leveren (spec, *Aan de bouwer*): **Deel A** herkomst (taak 1–4), **Deel B** meting en lokaal signaal (taak 5–11), **Deel C** lane en forge-uitbreiding (taak 12–18). B hangt niet van A af; C hangt van B af. Elke PR: `No issue:`-regel of `Refs #325 — <reden>` (de issue sluit pas met deel C), een `changelog.d/`-fragment, `go run ./cmd/lighthouse init --upgrade` bij een wijziging onder `pack/`.

## Global Constraints

- Artefacten (commits, PR's, issues, docs, specs/plannen) in het Nederlands; code, namen, comments en bestandsnamen in het Engels (`code_language`).
- Go volgens `/lighthouse-go-standard`; tests volgens `/lighthouse-test-standard` (elke test faalt als het gedrag breekt).
- Statussen: `current`, `behind`, `error`; alleen de lokale meting kent ook `ahead`. Statussen worden nooit samengevoegd (per pin een `upstream`- en een `local`-uitslag).
- Een pin die niet te meten is, is `error`, nooit `current`. Exitcode 1 zodra één uitslag `error` is, anders 0.
- Skillpins alleen onder `pack/*/skills/`, nooit onder `.claude/skills/` of `.agents/skills/`.
- Pinsleutels: skill = skillmap relatief aan `pack/` (bv. `core/skills/test-standard`); bestand = `path` uit `SOURCES.toml`; plugin/tool = naam van `[pins.<naam>]`.
- De meting voert geen upstream-code uit: bare partial clone `--filter=blob:none`, geen checkout, geen hooks, geen submodules.
- Releases: gepagineerd tot de laatste pagina, zonder drafts en prereleases; codex tagt `rust-v0.169.0` (`tag_prefix`), default `v`.
- Lane-PR is een **draft**, zonder `Closes`, zonder board-item en milestone, body begint met `No issue: <reden>`. De lane roept `MergePR` nooit aan.
- Lane-commits: auteur en committer `github-actions[bot]` `<41898282+github-actions[bot]@users.noreply.github.com>`; de GitHub App uit `[ci]` pusht.
- Upstream-tekst in een body staat altijd in een fenced codeblok met een fence langer dan elke backtickreeks in de tekst; body < 65.536 tekens.
- Workflow: één `concurrency`-groep, `cancel-in-progress: false`.
- Beginwaarden in `lighthouse.toml`: superpowers `7.0.2`, kenn-forge `0.5.1` (`kenn-io/forge`, `version_args = ["version"]`), roborev `0.69.0` (`version_args = ["version"]`), codex `0.157.0` (`tag_prefix = "rust-v"`).
- `lighthouse init` meldt pin-afwijkingen alleen op stderr; exitcode en stdout (`No changes.`) blijven ongewijzigd. De controller (tick, dispatch) doet niets met pins.

## Review Focus

Gevallen die de spec impliceert maar geen taak-test vanzelf raakt; elk heeft een test in de genoemde taak.

1. `upstream-path` met voorloop-`/` of afsluitende `/`, en `upstream` als `https://github.com/o/r.git` of `…/tree/main/x`: verwacht `owner/repo` genormaliseerd, geen valse `error` (taak 6).
2. `lighthouse.toml` zonder `[pins]`-sectie of met een pin zonder `version`: zonder sectie geen plugin/tool-pins en exit 0; een pin zonder `version` is `error` (taak 5).
3. Upstream met een andere default branch dan `main` (bv. `master`): de default is `HEAD` van de remote, geen hardcoded naam (taak 7).
4. Een rollende branch `pins/<sleutel>` die al op origin staat uit een eerdere, half mislukte run: de lane werkt hem bij en maakt geen dubbele PR (taak 16).
5. Een binair bestand of bestand zonder eindregel in een upstream-map bij de 3-way-merge: conflict-issue in plaats van een kapotte PR (taak 16).
