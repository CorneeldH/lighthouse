Wait, but why?

Two levels. The loop follows the work from an idea to main, phase by phase, across sessions. This map zooms in on one session. It follows one turn from the prompt to the stop, and answers "why does it stop me now?": which skill loads before the model writes, and which hook steps in at each moment, on which tool, from which pack, and what it does.

Instructions ask, hooks check. AGENTS.md (which Claude Code reads through CLAUDE.md), skills and agents are text that the model reads. The model follows that text most of the time. It can still lose a rule late in a long session, or decide that a rule does not apply. A hook is a script that Claude Code itself runs on an event, outside the model. It runs every time, also for the tool calls of a subagent, whatever the model remembers.

A rule sets the norm, a hook steps in. Each hook is the counterpart of a rule in AGENTS.md or a skill. The rule carries the norm beforehand, so an agent that follows it rarely meets the hook. The hook steps in at the moment itself, with a warning or with a hard line, as the headers of main-commit-guard.sh and worktree-guard.sh explain. When a hook blocks, its message goes back to the agent, which reads why and corrects its step. A skill and its hook often come as a pair. On this map, go-writing loads before the model writes Go, and gofmt and go-check check what it wrote. On the loop, /lighthouse-verify-pr writes the PR body that pr-create-gate checks.
