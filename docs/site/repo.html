Wait, but why?

The tree is your repository. Each coloured row is a place lighthouse init writes; the grey rows are what was already yours, and they stay. The switch shows what init adds and which files of yours it edits. An arrow ↗ leads to where that part is explained.

.lighthouse/ holds what the parts of lighthouse share. lib/ is the Python library the hooks, skills and scripts import. scripts/ holds the scripts that skills and the test gate run. headings.toml lists the headings that code and skills read as a contract, with one variant per language. manifest.toml records what init installed, with a checksum per part it installed.

.claude/settings.json gets the hooks of lighthouse and its permissions.allow rules. The rest of the file is yours.

host.toml holds the settings of this machine. The first init proposes one with the name of the machine and its Tailscale address, only when there is none yet and tailscale ip answers, and asks before it writes, unless you pass --yes. Commands such as lighthouse serve, tick and usage read it, and so do some skills and hooks. It is not in the repository, so another machine does not have it until you write one there.
